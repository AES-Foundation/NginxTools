# NGINXTOOLS

Кроссплатформенная утилита для управления NGINX: запуск, плавный перезапуск, корректное завершение, обновление IP-диапазонов, обновление NGINX и резервное копирование.

## Возможности

- **startup** — запуск NGINX с предварительной проверкой конфигурации.
- **restart** — плавный перезапуск (`nginx -s reload`), при котором текущие соединения не рвутся. Если в конфиге ошибка, NGINX продолжает работать со старой рабочей конфигурацией.
- **shutdown** — корректное завершение (`nginx -s quit`) с ожиданием окончания активных запросов и принудительным kill по истечении таймаута.
- **update-ips** — загрузка актуальных IP-диапазонов Cloudflare и других сервисов, генерация `real_ip.conf` и отдельных `.conf`-файлов.
- **upgrade** — обновление или понижение версии NGINX с полным бэкапом и автоматическим откатом при ошибке.
- **backup** — восстановление NGINX из резервной копии.
- **Автоопределение** каталога NGINX рядом с исполняемым файлом.
- **Внешний файл настроек** — не нужно пересобирать приложение.
- **Single-file публикация** — один бинарник, никаких зависимостей.

## Требования

- .NET 10 SDK — **только для сборки**.
- NGINX (Windows или Linux).

Готовые релизы публикуются как self-contained single-file бинарники: на целевой машине .NET не требуется.

## Структура каталогов

Пример расположения файлов NGINX:

```text
my-server/
├── nginxtools.exe      <-- ваш бинарник
└── nginx/              <-- ваш NGINX
    ├── nginx.exe
    ├── conf/
    └── ...
```

Утилита ищет NGINX в следующем порядке:

1. Аргумент `--nginx-dir`.
2. Переменная среды `NGINX_DIR`.
3. Поле `nginxDir` в `nginxtools.settings.json`.
4. Автоопределение рядом с исполняемым файлом:
   - `./nginx`
   - текущий каталог
   - `../nginx`

## Команды

| Команда | Описание |
|---|---|
| `init` | Установить базовый NGINX. |
| `startup` | Запустить NGINX с проверкой конфигурации. |
| `restart` | Плавный перезапуск (`nginx -s reload`). |
| `shutdown` | Плавное завершение (`nginx -s quit`) с fallback kill. |
| `update-ips` | Обновить доверительные IP-диапазоны. |
| `upgrade` | Обновить NGINX до выбранной версии. |
| `backup` | Восстановить NGINX из резервной копии. |
| `backup --list` | Показать список бэкапов. |
| `backup --time <YYYYMMDD-HHMMSS>` | Выбрать конкретный бэкап. |
| `backup --keep` | Не удалять бэкап после восстановления. |
| `backup --yes` | Не запрашивать подтверждение. |
| `status` | Показать текущий статус. |
| `version` | Показать версию установленного NGINX. |
| `help` | Показать справку. |

Примеры:

```bash
nginxtools startup
nginxtools restart
nginxtools shutdown
nginxtools update-ips
nginxtools update-ips --no-reload
nginxtools upgrade
nginxtools backup --list
nginxtools backup --time 20260915-140213
```

## Конфигурация

Файл конфигурации `nginxtools.settings.json` располагается рядом с исполняемым файлом `nginxtools`.

```json
{
  "nginxDir": "F:\\Servers\\nginx",
  "autoDetectNginx": true,
  "shutdownGraceTimeoutSeconds": 30,
  "realIpHeader": "CF-Connecting-IP",
  "realIpRecursive": true,
  "backupsDir": null,
  "removeOldBackups": false,
  "ipSources": [
    {
      "name": "cloudflare",
      "enabled": true,
      "ipv4Url": "https://www.cloudflare.com/ips-v4",
      "ipv6Url": "https://www.cloudflare.com/ips-v6",
      "outputFile": "cloudflare_set_real_ip_from.conf"
    }
  ]
}
```

### Основные поля

| Поле | Описание | По умолчанию |
|---|---|---|
| `nginxDir` | Явный путь к каталогу NGINX. `null` — использовать автоопределение. | `null` |
| `autoDetectNginx` | Искать NGINX рядом с бинарником. | `true` |
| `shutdownGraceTimeoutSeconds` | Таймаут плавного завершения перед принудительным kill. | `30` |
| `realIpHeader` | Заголовок, который передаёт настоящий IP. | `CF-Connecting-IP` |
| `realIpRecursive` | Рекурсивный поиск. Будет пропускать доверенные серверы в списке. | `true` |
| `backupsDir` | Каталог для бэкапов. `null` — рядом с NGINX: `<nginxDir>-backups`. | `null` |
| `removeOldBackups` | Удалять старые бэкапы перед созданием нового. | `false` |
| `ipSources` | Источники IP-диапазонов. | Cloudflare |

> [!WARNING]
> `removeOldBackups: true` означает, что останется только один бэкап — самый свежий. Используйте, если у вас много инсталляций или ограничено место на диске.

## Обновление IP-диапазонов

Утилита скачивает актуальные диапазоны IP-адресов с указанных вами URL и генерирует набор конфигурационных файлов NGINX для восстановления реального IP-адреса клиента.

### Быстрый старт

```cmd
nginxtools update-ips
```

Что происходит:

1. Для каждого активного источника скачиваются списки IPv4/IPv6.
2. Генерируется отдельный `.conf`-файл на каждый источник.
3. Генерируется сводный файл `conf/real_ip.conf` с директивой `real_ip_header` и `include` на каждый активный источник.
4. Если в `nginx.conf` уже подключён `real_ip.conf` и что-то изменилось — NGINX автоматически перезагружается плавно, без разрыва соединений.

### Что вы увидите в выводе

```text
=== Обновление IP-диапазонов ===

[cloudflare] обновление...
[my-proxy] обновление...
Сводный файл real_ip.conf обновлён.

--- Результат ---
[SUCCESS] cloudflare           обновлён        15 IPv4, 7 IPv6
[SUCCESS] my-proxy             без изменений   8 IPv4

В ваш nginx.conf ещё не добавлен include. Откройте файл:
     F:\Servers\nginx\conf\nginx.conf
   и внутри блока http { ... } добавьте строку:
     include conf/real_ip.conf;

Обнаружены изменения. Проверяем конфигурацию и перезагружаем NGINX...

NGINX успешно перезагружен.
```

### Первый запуск — что делать

1. Запустите:

   ```bash
   nginxtools update-ips
   ```

2. Если утилита сообщит, что `include` ещё не добавлен, откройте `nginx.conf` и **внутри блока `http { ... }`** добавьте строку:

   ```nginx
   include conf/real_ip.conf;
   ```

3. Примените изменения:

   ```bash
   nginxtools restart
   ```

После этого все дальнейшие запуски `nginxtools update-ips` или `nginxtools startup` будут автоматически подхватывать изменения, если они есть, и не трогать NGINX, если диапазоны не изменились.

### Флаги команды `update-ips`

| Флаг | Описание |
|---|---|
| `--no-reload` | Только записать файлы, **не перезагружать** NGINX. |

Полезно для деплоя, когда обновление IP и reload — отдельные стадии.

### Настройка источников

Список источников задаётся в `nginxtools.settings.json` в поле `ipSources`. Каждый источник — это объект:

| Поле | Обязательно | Описание | По умолчанию |
|---|---:|---|---|
| `name` | да | Имя источника для логов и подсказок. | `cloudflare` |
| `enabled` | нет | Отключить без удаления — просто поставить `false`. | `true` |
| `ipv4Url` | нет | URL со списком IPv4-диапазонов (по одному в строке). | `https://www.cloudflare.com/ips-v4` |
| `ipv6Url` | нет | URL со списком IPv6-диапазонов. | `https://www.cloudflare.com/ips-v6` |
| `outputFile` | да | Имя выходного `.conf`-файла относительно `conf/` NGINX. | `cloudflare_set_real_ip_from.conf` |

#### Заменить Cloudflare на свой сервис

Удалите дефолтный объект и добавьте свой:

```json
{
  "ipSources": [
    {
      "name": "my-cdn",
      "enabled": true,
      "ipv4Url": "https://cdn.example.com/ips-v4.txt",
      "ipv6Url": null,
      "outputFile": "my_cdn_set_real_ip_from.conf"
    }
  ]
}
```

#### Добавить сервис рядом с Cloudflare

Оставьте дефолтный объект и добавьте новый:

```json
{
  "ipSources": [
    {
      "name": "cloudflare",
      "enabled": true,
      "ipv4Url": "https://www.cloudflare.com/ips-v4",
      "ipv6Url": "https://www.cloudflare.com/ips-v6",
      "outputFile": "cloudflare_set_real_ip_from.conf"
    },
    {
      "name": "my-proxy",
      "enabled": true,
      "ipv4Url": "https://internal.example.com/proxy-ips.txt",
      "ipv6Url": null,
      "outputFile": "my_proxy_set_real_ip_from.conf"
    }
  ]
}
```

#### Отключить источник, не удаляя его

```json
{
  "name": "cloudflare",
  "enabled": false,
  "...": "..."
}
```

### Заголовок `real_ip_header`

Директива `real_ip_header` — уровня `http`, поэтому она одна на все источники. Задаётся в настройках:

```json
{
  "realIpHeader": "CF-Connecting-IP",
  "realIpRecursive": true
}
```

> [!NOTE]
> Если у вас несколько источников с разными заголовками — это ограничение NGINX, не утилиты. Решается через отдельные `server { real_ip_header ...; }` блоки.

### Автоматизация

**Windows (Планировщик заданий):**

```text
Программа:      C:\path\to\nginxtools.exe
Аргументы:      update-ips
Расписание:     ежедневно, 03:00
```

**Linux (systemd timer):**

> [!NOTE]
> Ещё не тестировалось.

## Обновление NGINX

Команда `upgrade` обновляет существующую установку NGINX, сохраняя все пользовательские файлы: конфиги, сертификаты, `.htpasswd`, статику, логи и сгенерированные `real_ip.conf` / `cloudflare_set_real_ip_from.conf`.

### Быстрый старт

```bash
nginxtools upgrade
```

Что происходит:

1. Утилита определяет текущую установленную версию (`nginx -v`).
2. Показывает список доступных версий — текущая исключена из списка.
3. Вы выбираете версию стрелками, `Enter` — подтверждение, `Esc` — отмена.
4. Утилита:
   - делает бэкап старого `nginx.exe` рядом (`nginx.exe.backup-YYYYMMDD-HHMMSS`);
   - останавливает NGINX плавно (`nginx -s quit`), если он был запущен;
   - скачивает новую версию во временный каталог;
   - копирует только `nginx.exe`, `docs/` и `contrib/`;
   - запускает `nginx -t`;
   - если проверка прошла — запускает NGINX обратно;
   - если проверка упала — **откатывает exe из бэкапа** и восстанавливает работу.

### Что НЕ трогается при обновлении

| Каталог/файл | Статус |
|---|---:|
| `conf/*` (включая `nginx.conf`) | не трогается |
| `conf/*.crt`, `conf/*.key`, `conf/*.pem` | не трогается |
| `conf/real_ip.conf` | не трогается |
| `conf/cloudflare_set_real_ip_from.conf` | не трогается |
| `conf/.htpasswd` | не трогается |
| `html/*` | не трогается |
| `logs/*` | не трогается |
| `temp/*` | не трогается |
| `cache/*` | не трогается |
| `cert_for_auth/*` | не трогается |
| `nginx.exe` | **обновляется** |
| `docs/*` | **обновляется** |
| `contrib/*` | **обновляется** |

### Пример вывода

```text
Текущая версия: 1.27.0
Каталог: F:\Servers\nginx

Получение списка версий с nginx.org... готово.

Выберите версию для установки:
↑↓ - навигация,  Enter - выбор,  Esc - отмена

    1.31.5       │ Mainline (разработка)   ↑
    1.30.4       │ Stable (стабильная)     ↑

Внимание: будут заменены только nginx.exe, docs/ и contrib/.
Файлы в conf/, html/, logs/, temp/, cache/ не затрагиваются.

Обновить 1.27.0 --> 1.31.5? [Y/n] y

Скачивание nginx-1.31.5 ██████████████████████████████ 100%  1.4 MB / 1.4 MB

[SUCCESS] Обновление завершено: 1.27.0 --> 1.31.5
Бэкап старого exe: F:\Servers\nginx\nginx.exe.backup-20260915-140213
NGINX был перезапущен автоматически.
```

### Понижение версии (откат)

Команда поддерживает и понижение — выбирайте любую версию ниже текущей. Полезно, если новая версия не подошла или возникла несовместимость с модулями.

```text
Понизить 1.31.5 --> 1.30.4? (откат на старую версию) [Y/n]
```

### Ограничения

- На Linux `upgrade` пока не поддерживается — там NGINX ставится через пакетный менеджер (`apt`, `dnf`) или собирается из исходников, и логика обновления другая. Поддержка появится в будущих версиях.

## Резервные копии и откат

Перед каждой командой `nginxtools upgrade` утилита автоматически создаёт **полный снимок каталога NGINX** — включая `conf/`, `html/`, `logs/`, `temp/`, сертификаты и всё остальное. Бэкап кладётся рядом с NGINX:

```text
F:\Servers\
├── nginx\                          <-- рабочий NGINX
└── nginx-backups\                  <-- каталог бэкапов
    ├── 20260915-140213\            <-- полный снимок
    ├── 20260915-140213.json        <-- метаданные
    ├── 20260915-150000\ 
    └── 20260915-150000.json
```

Если обновление упало — утилита автоматически восстанавливает NGINX из только что созданного бэкапа. Ничего не теряется.

### Настройка

В `nginxtools.settings.json`:

```json
{
  "backupsDir": null,
  "removeOldBackups": false
}
```

| Поле | Описание | По умолчанию |
|---|---|---|
| `backupsDir` | Каталог для бэкапов. `null` — рядом с NGINX (`<nginxDir>-backups`). | `null` |
| `removeOldBackups` | Удалять старые бэкапы перед созданием нового. | `false` |

> [!WARNING]
> `removeOldBackups: true` означает: останется только один бэкап — самый свежий. Используйте, если у вас много инсталляций или ограничено место на диске.

### Восстановление из бэкапа

#### Интерактивно

```bash
nginxtools backup
```

Утилита покажет список доступных бэкапов, вы выберете стрелками:

```text
  Выберите бэкап для восстановления:
  ↑↓ - навигация,  Enter - выбор,  Esc - отмена

  > 20260915-150000  v1.27.0    2026-09-15 15:00:00  before upgrade 1.27.0 --> 1.31.5
    20260915-140213  v1.27.0    2026-09-15 14:02:13  before upgrade 1.26.0 --> 1.27.0
```

#### По имени

```bash
nginxtools backup --time 20260915-140213
```

#### Только посмотреть список

```bash
nginxtools backup --list
```

### Флаги команды `backup`

| Флаг | Описание |
|---|---|
| `--list` | Показать список бэкапов и выйти. |
| `--time <имя>` | Выбрать конкретный бэкап (`YYYYMMDD-HHMMSS`); можно указать префикс. |
| `--keep` | Не удалять бэкап после успешного восстановления. |
| `--yes` | Не запрашивать подтверждение. |

### Что происходит при восстановлении

1. NGINX останавливается плавно (`nginx -s quit`), если он был запущен.
2. Текущий каталог NGINX переименовывается в `nginx.trash-<random>`.
3. Содержимое бэкапа копируется на место NGINX.
4. Запускается `nginx -t`.
   - Успех → `trash` удаляется, NGINX перезапускается, если был запущен.
   - Ошибка → `trash` возвращается на место, NGINX перезапускается со старой версией.
5. После успешного восстановления использованный бэкап **удаляется**.
   - По флагу `--keep` можно сохранить.

### Пример вывода

```text
Текущий NGINX будет ЗАМЕНЁН содержимым бэкапа 20260915-140213.
Версия в бэкапе:  1.27.0
Создан:           2026-09-15 14:02:13
Причина создания: before upgrade 1.27.0 --> 1.31.5

Продолжить восстановление? [y/N] y

[SUCCESS] NGINX восстановлен из бэкапа 20260915-140213.
Версия: 1.27.0
Использованный бэкап удалён: 20260915-140213
```

### Просмотр содержимого бэкапа вручную

Бэкап — это обычный каталог `..\nginx-backups\20260915-140213`.

При необходимости можно что-то достать руками, скопировать в рабочую установку или удалить бэкап самостоятельно.

## Безопасность и идемпотентность

- Если содержимое файла не изменилось — файл не перезаписывается, NGINX не перезагружается.
- Запись атомарная: сначала во временный файл, потом `File.Move`.
- UTF-8 без BOM и LF-окончания строк — NGINX не должен ругаться на Windows/Linux-перенос.
- Проверка `nginx -t` перед reload. Если конфиг сломан — NGINX продолжит работать со старой версией.
- Перед `upgrade` создаётся полный бэкап. При ошибке выполняется автоматический откат.

---

## Ограничения

- `upgrade` на Linux пока не поддерживается.
- `init` для Linux в текущей версии не поддерживается — используйте пакетный менеджер (`apt`, `dnf`) или сборку из исходников.
- `real_ip_header` — директива уровня `http`, поэтому она одна на все источники. Для разных заголовков нужны отдельные `server { real_ip_header ...; }` блоки.
- systemd timer для автоматического обновления IP ещё не тестировался.
